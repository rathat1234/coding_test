# Day 24. 디바운싱 (Debouncing) 알고리즘

## 문제 설명

버튼이나 스위치와 같은 입력 장치는 실제로 상태가 한 번 변경될 때 순간적으로 여러 번의 `0/1` 신호가 발생하는 **채터링(Chattering)** 현상이 발생할 수 있다.

이러한 노이즈를 제거하기 위해 일정 횟수 이상 동일한 입력이 연속으로 들어왔을 때만 실제 상태가 변경되도록 **디바운싱(Debouncing) 알고리즘**을 구현한다.

## 요구사항

* **입력:** 노이즈가 섞인 `0/1` 입력 배열
* **출력:** 노이즈가 제거된 안정화된 출력 값
* **제약조건:**

  * 연속된 `N`번의 샘플링이 동일할 때만 상태 변경
  * 조건을 만족하지 못하면 현재 상태 유지
  * 입력이 이전 상태로 돌아가면 카운터 리셋

## 실행 결과

```text
=== Day 24: Button Debouncing Logic ===
Condition: 3 consecutive samples required.

Step | Raw Input | Counter | Output (Stable)
-----+-----------+---------+----------------
   1 |     0     |    0    |       0
   2 |     0     |    0    |       0
   3 |     1     |    1    |       0  <-- 노이즈 발생 (카운트 시작)
   4 |     0     |    0    |       0  <-- 다시 0 복귀 (카운트 리셋!)
   5 |     1     |    1    |       0  <-- 진신호 시작
   6 |     1     |    2    |       0
>> [State Changed] to 1
   7 |     1     |    0    |       1  <-- 3회 연속 성공으로 상태 변경
   8 |     1     |    0    |       1
   9 |     1     |    0    |       1
  10 |     0     |    1    |       1  <-- 노이즈 무시
```

## 실행 과정

### Phase 1. 노이즈 발생

초기 안정 상태는 `0`이다.

3번째 샘플에서 `1`이 입력되지만 아직 3번 연속으로 들어오지 않았기 때문에 상태를 변경하지 않는다.

```text
Step 3
Raw Input = 1
Counter   = 1
Output    = 0
```

다음 샘플에서 다시 `0`이 들어오므로 카운터가 리셋된다.

```text
Step 4
Raw Input = 0
Counter   = 0
Output    = 0
```

따라서 순간적으로 발생한 `1` 신호는 노이즈로 판단된다.

### Phase 2. 실제 입력 발생

5번째 샘플부터 `1`이 연속으로 입력된다.

```text
Step 5 → Counter = 1
Step 6 → Counter = 2
Step 7 → Counter = 3
```

설정된 조건인 **3회 연속 입력**을 만족했으므로 안정 상태가 `1`로 변경된다.

```text
>> [State Changed] to 1
```

### Phase 3. 상태 유지

이후 `1`이 계속 입력되므로 안정 상태도 `1`을 유지한다.

```text
Step 7 → Output = 1
Step 8 → Output = 1
Step 9 → Output = 1
```

10번째 샘플에서 `0`이 한 번 입력되지만 아직 3회 연속 `0`이 아니므로 상태를 변경하지 않는다.

```text
Step 10
Raw Input = 0
Counter   = 1
Output    = 1
```

즉, 순간적인 `0` 신호 역시 노이즈로 처리된다.

## 핵심 알고리즘

안정 상태(`stable_state`)와 연속 입력 횟수(`counter`)를 관리한다.

```text
입력 == 현재 안정 상태
        ↓
    Counter = 0

입력 != 현재 안정 상태
        ↓
    Counter 증가
        ↓
Counter >= N ?
   ↓          ↓
  Yes         No
   ↓           ↓
상태 변경    상태 유지
Counter = 0
```

이번 문제에서는 `N = 3`으로 설정하였다.

## 예시

현재 안정 상태가 `0`이고 다음과 같은 입력이 들어온다고 가정한다.

```text
0 0 1 0 1 1 1
```

처리 결과:

```text
Raw Input :  0  0  1  0  1  1  1
Counter   :  0  0  1  0  1  2  3
Stable    :  0  0  0  0  0  0  1
```

`1`이 3번 연속 입력된 마지막 시점에서만 안정 상태가 `1`로 변경된다.

## 임베디드 활용

디바운싱은 다음과 같은 입력 장치에서 활용할 수 있다.

* 기계식 버튼
* 스위치
* GPIO 입력
* 엔코더 입력
* 키패드
* 센서의 디지털 출력

특히 STM32와 같은 MCU에서 GPIO 버튼을 읽을 때 순간적인 입력 변화로 인해 버튼이 여러 번 눌린 것처럼 인식되는 문제를 방지하는 데 사용할 수 있다.
